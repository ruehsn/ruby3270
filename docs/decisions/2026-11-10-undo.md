# Undo with Ctrl+Z (2026-11-10)

## Summary
Ctrl+Z (also Edit > Undo) takes back the last paste, snippet, spelling fix or run of typing. It puts the
input fields' text and the cursor back the way they were. It works until the host sends a new screen.
Undo lives in the tab's controller, on its worker thread, next to the paste and typing it takes back.

This session also checked whether the left and right arrows get the same speed-up as the down arrow.
They do, so no change was made (see the last decision).

## Decisions
### Undo saves the input fields, not the keystrokes
- **What:**
  - Before each undoable action, `undo_point` reads the screen and saves each input field's text, plus
    the cursor position.
  - On an unformatted screen, it saves each row instead.
  - Undo puts back only the fields whose text differs now: it moves to the field, sends Erase EOF, then
    types the old text. On an unformatted screen, rows are typed over with insert mode switched off.
  - Up to 20 steps are kept (`UNDO_LIMIT`).
- **Why:**
  - The user asked for Ctrl+Z mainly to take back a paste.
  - A 3270 engine has no undo of its own. Saving what the fields held works for any action, including a
    multi-line paste that spans many fields.
- **Where:** [controller.rb](../../lib/tn3270/gui/controller.rb) (`undo`, `undo_point`, `undo_now`,
  `restore_fields`, `restore_rows`).

### Typing is grouped into one step
- **What:**
  - Typed characters and the editing keys (Backspace, Delete, Erase EOF, Erase Input) join one undo
    step.
  - The step ends at the next other action: a cursor move, another key, a paste or a snippet.
- **Why:** like a text editor, so one Ctrl+Z takes back a word you typed, not one letter. It also keeps
  screen reads to one per run of typing, not one per key.
- **Where:** `Controller#typing`, `@typing`, `EDIT_KEYS`, `press`, `move_to`.

### Undo stops at the host's next screen
- **What:**
  - Sending an AID key (Enter, PF, PA, Clear...) clears the undo list. So do connecting and
    disconnecting.
  - Each undo step records the host's record count (`records_received`). If the host has sent anything
    since, undo refuses: "Can't undo: the host has changed the screen since".
  - Undo also refuses if the screen's input fields are no longer in the same places.
- **Why:** once the host has answered, its new screen replaces what was there, and putting old text into
  it would be a guess.
- **Where:** `send_key` (calls `forget_undo`), `undo_now`, `restore_fields`.

### Password fields are left alone
- **What:** no special code. A hidden field always reads as blank, so it never looks changed and undo
  never types into it.
- **Why:** the app can't read what's in a password field, so it couldn't put the right text back.
- **Where:** `Screen#make_cell` (hidden cells read as spaces).

### Ctrl+Z is a key binding like the others
- **What:**
  - A new `undo` action is bound to Ctrl+Z by default. It can be changed in Keys > Keyboard Mapping.
  - Edit > Undo is the first item in the Edit menu and shows its shortcut.
- **Why:** Ctrl+Z was free, and it's the key users expect for undo.
- **Where:** [keymap.rb](../../lib/tn3270/gui/keymap.rb) (`ACTIONS`, `DEFAULTS`, `action_result`),
  [program.rb](../../lib/tn3270/gui/program.rb) (Edit menu, `SHORTCUTS`),
  [terminal_window.rb](../../lib/tn3270/gui/terminal_window.rb) (`perform`, `undo`).

### Arrow keys: no change needed
- **What:** nothing was changed.
- **Why:**
  - The user asked whether left and right get the down arrow's speed-up.
  - That speed-up is general: the window redraws as soon as anything on the screen changes.
  - The cursor position is part of what counts as a change, so every arrow key gets it.
  - Measured against the fake host's editor, all four arrows took the same time from key press to new
    cursor position: a median of about 15 ms.

## Follow-ups
- There is no redo (Ctrl+Y).
- A field that undo puts back stays marked as changed, so the host receives its original text on the
  next Enter.
- The tests cover the controller against the fake host. Edit > Undo and Ctrl+Z weren't tried in the real
  window.
